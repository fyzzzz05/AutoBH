# 阳光打卡

AutoBH 的 `ygdk` 功能移植自 [BUAASubnet/UBAA](https://github.com/BUAASubnet/UBAA) 的本地阳光接口，实现参考固定于提交 `e8a397fcb35a68147eee65a94c66ffb84e2f09fe`。保留学校的 OAuth 登录、分类/运动项目、次数优先级、分页记录、图片上传和提交字段转换。MIT 版权声明随 Python 包和 App 分发，见 `src/autobh/third_party/UBAA-LICENSE.txt`。

## App

选择人员，在“阳光打卡”行绑定账号。已绑定上课或博雅时，可勾选复用其密码；AutoBH 保存凭据来源，不复制原密码，也不会改变原功能的开关。也可单独输入学校密码，优先保存到系统钥匙串。移除阳光绑定不删除原上课/博雅凭据。

阳光需要先建立统一认证和移动校园两层登录，再交换阳光授权码。旧版只完成统一认证时会停在移动校园登录页，出现“未取得阳光登录授权”。学校还会把 OAuth 授权码放在 `#/home?code=…` 的 hash 路由中，旧版仅检查普通查询参数而漏读。0.1.6 已补齐移动校园 CAS 初始化、兼容独立登录表单，并支持两种授权回调位置。

在“阳光打卡 → 查看记录”顶部，可点“学校登录/授权”打开学校页面检查登录、验证码或账号状态；回到 App 点“重新连接”。浏览器 Cookie 不会导入 AutoBH，重新连接使用当前人员绑定的学校密码。密码有变化时点“更新账号”，取消复用旧密码并输入新密码。此操作只恢复只读查询，不提交运动记录。

“查看记录”展示学期、本周、今日次数和历史运动记录。“刷新数据”只读取学校统计，不提交打卡；学校返回的有效学期次数优先展示。没有数据时显示 `—`，跨日/跨周的旧缓存不当作当前周期的次数。

阳光开关和“管理后台”的阳光任务仅控制**每 30 分钟同步数据**。新安装不自动绑定人员、不启动任务；暂停自动同步后仍能手动刷新或提交。

“一键四连”可一次确认多段运动记录，本周目标按用户要求设为 4 次；先查询实时周次数，只提交差额。记录限本周，运动时段至少间隔 10 分钟。点击后按当前北京时间向前自动生成所需时段，默认每段 30 分钟、段间隔 10 分钟，运动默认选择跑步；只补本周差额。各段须按实际运动情况核对、修改，结束后才能一起提交。也可修改第一段后点“按首段同步其余时间”。地点会带入最近记录，图片仍由用户选择。发生异常立即暂停后续条目，重试沿用原编号并跳过已成功的条目。此操作复用单条提交接口与同一份持久化防重记录。

新增打卡时，选择学校返回的运动项目，填写北京时间的实际开始/结束时间、地点并上传运动照片。核对页面确认后才会上传图片和提交，默认不公开到广场。时间必须同日、结束晚于开始且不晚于当前时间。图片上限 8 MB，支持 JPG/PNG/WebP。

提交编号和内容摘要在本地持久化，成功记录不会重复提交。网络超时或服务器响应异常时保留“结果未确认”，不会自动重试；先刷新学校历史记录核对结果。成功提交后的统计刷新失败会单独提示，不把已成功的提交显示为失败。

数据目录默认 `~/.autobh/ygdk`，可用 `AUTOBH_YGDK_HOME` 覆盖。密码与缓存按人员隔离，账号文件和缓存使用原子替换与 0600 权限。学校会话与 token 仅保留在当前请求的内存中。

## CLI

```bash
# 复用已绑定的上课/博雅密码
autobh account add ygdk 学号 --reuse-password
# 或输入学校密码
autobh account add ygdk 学号

autobh ygdk refresh --user 学号
autobh ygdk records --user 学号 --page 2
autobh ygdk status --user 学号             # 仅本机缓存
autobh service start --feature ygdk        # 仅周期同步
autobh feature disable ygdk --user 学号

autobh ygdk submit --user 学号 --item 项目ID \
  --start 2026-10-16T17:00 --end 2026-10-16T18:00 \
  --place 沙河操场 --photo /绝对路径/运动照片.jpg --yes
```

项目 ID 从刷新结果的 `items` 获取，示例时间需替换为本次实际运动信息。提交前 CLI 输出提交编号，重试可通过 `--request-id` 沿用该编号。

## 验证边界

自动测试使用 MockTransport、隔离目录和示例页面，覆盖只读查询、字段转换、账号隔离、次数优先级、无缓存、刷新失败保留数据、提交确认、超时及重复提交。没有使用真实账号提交或上传运动照片；真实网络可用性和学校对活动的审核以实际返回为准。

批量 CLI 使用 `autobh ygdk batch --user 学号 --item 项目ID --place 地点 --photo 图片路径 --plan 时间计划.json --yes`。计划文件为最多四个对象的 JSON 数组，每个对象含 `startTime`、`endTime`（北京时间 `yyyy-MM-ddTHH:mm`）。
